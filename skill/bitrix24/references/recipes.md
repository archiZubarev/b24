# Проверенные приёмы

Каждый проверен на облачном портале в 2026 году; даты — когда.

## История стадий: что было с объектом на дату

Карточка знает только нынешнюю стадию, а `CLOSEDATE` правят руками. Историю
переходов пишет сам портал, и правке она не поддаётся (05.10.2026).

- Метод `crm.stagehistory.list`, `entityTypeId`: 2 — сделки, 1 — лиды, 31 — счета.
- Ответ в `result.items`, страница 50, дальше по `next`; `order[ID]=ASC`.
- Запись: `OWNER_ID`, `CREATED_TIME` (с поясом портала), `STAGE_ID`,
  `STAGE_SEMANTIC_ID` (P/S/F), `TYPE_ID` (1 — создание, 2 — промежуточная,
  3 — финальная), `CATEGORY_ID`.
- Состояние на дату: записи объекта по времени → последняя не позже даты → её
  семантика. Сравнивать в поясе портала. Провалили и вернули — F, затем P:
  нельзя просто искать «была ли F».
- Провалов в цепочке бывает два подряд («провалена» → «анализ причины») —
  моментом провала считать первый.
- Быстро в два захода: сначала одним запросом только провалы
  (`filter[OWNER_ID]` = массив, `STAGE_SEMANTIC_ID=F`, `select[]=OWNER_ID`), потом
  полную историю только по ним. 300 сделок: 15 с → 2,5 с.
- У объекта без переходов история всё равно есть — запись о создании.

## Файлы из чата сделки

Чат сделки видит только участник: права администратора доступа не дают
(`ACCESS_ERROR`). Читать ключом человека, который сидит в этих чатах
(15.09.2026). Права вебхука: `crm`, `user`, `im`, `disk`.

1. ID чата: `im.chat.get` с `ENTITY_TYPE=CRM`, `ENTITY_ID=DEAL|<id сделки>`.
   На некоторых порталах роботы кладут ID чата в поле сделки — тогда он есть
   сразу в `crm.deal.list`.
2. Сообщения и файлы: `im.dialog.messages.get`, `DIALOG_ID=chat<ID>`, `LIMIT`
   до 50, листать назад через `LAST_ID` = минимальный id пачки. Рядом с
   `messages` лежит `files`: id, имя, расширение, размер, автор, дата.
3. Ссылка: `disk.file.get` по id файла → `DOWNLOAD_URL` (нужно право `disk`).
4. Скачать обычным GET. Проверить первые байты: `PK` — xlsx/docx/zip,
   `D0 CF 11 E0` — старый xls/doc. Пришла HTML-страница — ссылка не
   авторизовалась.

Побочные эффекты: `im.dialog.messages.get` прочитанными не отмечает (по
документации). `im.disk.folder.get` не вызывать — неясно, не создаёт ли он
папку чата. `messages[].params` бывает пустым массивом, а не объектом.

## Где появились новые сообщения — не читая все чаты

`im.recent.list` (право `im`) — недавние чаты владельца ключа по последнему
сообщению (25.09.2026):

- `SKIP_OPENLINES=Y`, `SKIP_DIALOG=Y` (без личных переписок), `LIMIT` до 200;
- листать назад: `LAST_MESSAGE_DATE` = дата последнего элемента, пока `hasMore`;
- у чата сделки `chat.entity_type=CRM`, `chat.entity_id=DEAL|<id>`; у сообщения
  `message.id`, `message.date`.

1 800 чатов за четыре недели — 9 запросов, 23 с. Дальше читать только
оживавшие чаты, `im.dialog.messages.get` пачками по 50. Метод только отдаёт
список: соседи `im.recent.hide`, `im.recent.pin`, `im.recent.unread` — запись.

## Что изменилось с прошлой сверки

Задача «быстро узнать, не появилось ли новое» — например, не вписал ли кто-то
номер мимо программы (16.10.2026):

- фильтр `filter[>=DATE_MODIFY]` со временем и поясом (RFC 3339), `select` —
  только нужные поля;
- отметка «сверено до» — `time.date_start` прошлого ответа минус 10–15 минут;
- первая страница со `start=-1` (без подсчёта): за пару часов правок обычно
  меньше 50, хватает одного вызова на 0,2–0,4 с; страница полная — дочитать
  всё «по ID»;
- первая сверка, когда отметки ещё нет, — за пару суток от полуночи.

Было 264 сделки за два дня и 3 с на каждое нажатие, стало 0,4 с.

## Сделки по списку ID

`crm.deal.list` с `filter[ID]` = массив до 50 ID, по команде на каждые 50 в
одной пачке: 19 594 сделки — 16 с (15.10.2026). Удалённых сделок в ответе
просто нет — это способ заметить удаление.

## Поля смарт-процесса

Создаются через `userfieldconfig.add` с `entityId = CRM_<id типа>`; отсюда
префикс `UF_CRM_<id>_` в кодах. Варианты списка — ключ `enum`, переименование
без смены ID — `userfieldconfig.update` с `userTypeId: enumeration`
(11.09.2026).

## Старые xls из чатов в Go

`excelize` читает только xlsx. Для старого `.xls` (печатные формы 1С)
проверена `github.com/shakinm/xlsReader`; `github.com/extrame/xls` падала на тех
же файлах (15.09.2026).
