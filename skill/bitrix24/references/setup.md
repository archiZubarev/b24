# Настройка у нового человека

Порядок: поставить `b24` → подключить MCP → создать вебхук в Битриксе →
сохранить ключ → проверить. Проводи человека по шагам, по одному за раз, и
после каждого проверяй результат (`b24 status`, `b24 check`), а не верь на слово.

## Установка

macOS (Терминал):

```bash
curl -fsSL https://raw.githubusercontent.com/archiZubarev/b24/main/install.sh | sh
```

Windows (PowerShell, обычный, не от администратора):

```powershell
irm https://raw.githubusercontent.com/archiZubarev/b24/main/install.ps1 | iex
```

Установщик кладёт программу (`~/.local/bin/b24` на Mac,
`%LOCALAPPDATA%\Programs\b24\b24.exe` на Windows), скилл в
`~/.claude/skills/bitrix24` и сразу запускает `b24 setup`. Если после установки
команда `b24` не находится — открыть новое окно терминала (PATH обновляется
только в новых окнах).

Эти команды скачивают и запускают программу из интернета — человек запускает
их сам в своём терминале. Ты можешь показать команду и объяснить, что она
делает, но не выполняй установку через Bash без его явного «да».

## MCP

`b24 setup` подключает на уровне пользователя (для всех папок):

- `b24-dev-mcp` — официальная документация REST: `https://mcp-dev.bitrix24.tech/mcp`.
  Без авторизации, к порталу не ходит. Инструменты: `bitrix-search`,
  `bitrix-method-details`, `bitrix-article-details`, `bitrix-event-details`.
- `b24` — свой сервер: `b24 mcp`. Инструменты `bitrix_keys`, `bitrix_read`,
  `bitrix_list_all`, `bitrix_batch`, `bitrix_write`.

Без утилиты `claude` в PATH `b24 setup --print` печатает команды для ручного
запуска. После подключения нужен новый разговор (или перезапуск Claude).

Удобно разрешить чтение без вопросов, а запись оставить с подтверждением: в
`~/.claude/settings.json` в `permissions.allow` добавить
`mcp__b24__bitrix_read`, `mcp__b24__bitrix_list_all`, `mcp__b24__bitrix_batch`,
`mcp__b24__bitrix_keys` и инструменты `mcp__b24-dev-mcp__*`. `bitrix_write`
туда не добавлять — пусть Claude Code спрашивает каждый раз.

Официальный MCP самого Битрикса для сотрудников (`mcp.bitrix24.tech`, вход
учёткой, включает администратор портала) — другая вещь: задачи, сделки, чаты
в рамках прав сотрудника, без смарт-процессов и настроек. Для выгрузок,
отчётов и работы со смарт-процессами вебхук через `b24` точнее и шире.

## Ключ: как создать входящий вебхук

Вебхук создаёт тот, от чьего имени будут запросы. Через него видно ровно то,
что этот человек видит в Битриксе: чужие сделки по правам CRM — нет; чаты
сделок — только где он участник (права администратора чаты не открывают).

1. В Битриксе: **Приложения → Разработчикам**.
2. Вкладка **Готовые сценарии → Другое → Входящий вебхук**.
3. Название — понятное, например «Claude, выгрузки».
4. **Права доступа** — отметить только нужные (таблица ниже).
5. Срок действия, если есть поле, — по задаче; бессрочный удобнее, временный безопаснее.
6. **Сохранить / Создать** и скопировать строку **«Вебхук для вызова rest api»**:
   `https://портал.bitrix24.ru/rest/123/abcd…/`.

Нет пункта «Разработчикам» или «Входящий вебхук» — создание вебхуков закрыто.
Администратор открывает: **Настройки → Настройки Битрикс24 → Безопасность →
Интеграции Битрикс24 → «Кому разрешить создавать входящие вебхуки»**. Если там
включено «Источник прав — Вайбкод-сервер», права берутся оттуда.

Если администратор отредактирует чужой вебхук, секретный код сменится, а
владельцем станет администратор — старая ссылка перестанет работать.

### Какие права отметить

Меньше прав — меньше беды при утечке ссылки. Бери то, что нужно сейчас, плюс
одно-два на ближайшую задачу. «Все галочки» не нужны: то, что вебхуку закрыто
(роботы стадий, события, встройки), закрыто не правами — см. rest.md.

| Задача | Права (scope) |
|---|---|
| Сделки, лиды, контакты, компании, смарт-процессы, стадии, история стадий | `crm` |
| Имена ответственных, сотрудники | `user` (или `user_brief` — только базовые поля) |
| Отделы, оргструктура | `department` |
| Чаты сделок, сообщения, недавние чаты | `im` |
| Файлы из чатов и с Диска (скачать) | `disk` (вместе с `im` для чатов) |
| Задачи | `task` |
| Запуск бизнес-процессов, их шаблоны | `bizproc` |
| Создание и правка пользовательских полей СПА | `userfieldconfig` + `crm` |
| Товары и каталог | `catalog` |
| Универсальные списки | `lists` |
| Календарь | `calendar` |
| Телефония, звонки | `telephony` (часть методов только приложению) |

Типовой набор для отчётов по CRM с чатами: `crm, user, im, disk`.

## Ключ: как сохранить

Ссылку не вставлять в чат с Claude. Два способа, оба в терминале у человека:

```bash
b24 add work              # спросит ссылку, ввод скрыт
b24 add work --clipboard  # возьмёт ссылку из буфера и сотрёт её из буфера
```

`b24` сразу спросит портал, чей это ключ и какие у него права, и покажет это.
Если портал ключ не принял — ключ не сохранится, ошибка скажет почему.

Имя ключа — короткое, по порталу или назначению: `work`, `lab`, `olga`,
`test`. Первый ключ становится основным. Дальше: `b24 list`, `b24 check`.

## Несколько ключей

```bash
b24 list                      # имена, порталы, пользователи, права; * — основной
b24 default lab               # сменить основной
b24 rename old-name new-name  # переименовать (ключ переносится в хранилище)
b24 call --key lab profile    # вызов конкретным ключом
b24 remove test               # удалить из хранилища (вебхук в Битриксе останется)
```

В MCP ключ выбирается параметром `key` у любого инструмента; пусто — основной.

## Перенос старых ключей из файлов

Если ключи лежали в файлах (`~/.portal_webhook` и т. п.):

```bash
b24 import work --file ~/.portal_webhook
```

Файл не трогается и не печатается — программы, которые его читают, работают
как раньше. Удалять его или нет, решает человек.

## Где лежат ключи и что видно

- macOS: Связка ключей, записи «Битрикс24 — ключ b24», сервис `b24`.
- Windows: Диспетчер учётных данных → Учётные данные Windows → `b24:<имя>`.
- Список без ссылок: `~/Library/Application Support/b24/keys.json`,
  `%AppData%\b24\keys.json`.

На macOS после обновления `b24` система один раз спросит «b24 хочет
использовать конфиденциальную информацию…» — это новая версия программы
просит доступ к своим записям. Нажать «Всегда разрешать».

## Если что-то не так

| Признак | Что делать |
|---|---|
| `b24: command not found` | новое окно терминала; проверить, что `~/.local/bin` (Windows — папка программы) в PATH |
| `INVALID_CREDENTIALS` при `add` или `check` | ссылку скопировали не целиком, вебхук удалён, истёк или владелец уволен — создать заново |
| `insufficient_scope` | в настройках вебхука отметить нужное право и сохранить, ссылка не меняется |
| портал перенаправил запрос на другой адрес | у портала сменился адрес — `b24 add` с новой ссылкой под тем же именем |
| инструментов `mcp__b24__*` нет | `b24 status`; `b24 setup`; новый разговор |
| macOS просит пароль Связки ключей при каждом вызове | в окне выбрать «Всегда разрешать», а не «Разрешить» |
