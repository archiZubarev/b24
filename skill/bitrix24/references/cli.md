# b24: команды и инструменты MCP

## Ключи

| Команда | Что делает |
|---|---|
| `b24 add <имя> [--clipboard] [--default]` | сохранить ключ; проверяет его на портале (`profile`, `scope`) |
| `b24 import <имя> --file <путь>` | перенести ключ из файла, файл не трогается |
| `b24 list [--json]` | ключи: имя, портал, пользователь, права; `*` — основной |
| `b24 check [<имя>\|--all]` | проверить ключ(и) на портале, обновить права в списке |
| `b24 rename <старое> <новое>` | переименовать |
| `b24 default <имя>` | сделать основным |
| `b24 remove <имя> [--yes]` | удалить из хранилища; без терминала — только с `--yes` |
| `b24 copy [<имя>] [--seconds 30]` | ссылка в буфер на N секунд — только человеку в терминале |

Имя ключа — буквы, цифры, `.`, `-`, `_`, до 40 знаков, регистр не важен.

`b24 copy` вне терминала отказывает намеренно: Claude и скрипты пользуются
ключом через `b24 call` и MCP, им сама ссылка не нужна. Не обходи это.

## Вызовы

```text
b24 call [--key имя] <метод> [ключ=значение ...] [--json '{...}'|@файл] [--all] [--limit N] [--raw]
```

- Параметры — в обозначениях документации: `id=12`, `'filter[STAGE_ID]=WON'`,
  `'filter[>DATE_MODIFY]=2026-10-01T00:00:00+03:00'`, `'select[]=ID'`,
  `'order[ID]=DESC'`. Значения уходят строками — портал их понимает.
- `--json` — параметры объектом (числа, булевы, вложенность), строкой или из
  файла `@params.json`; сливается с `ключ=значение`.
- `--all` — все страницы списочного метода (первая страница + пачки по 50
  страниц); `--limit N` — не больше N строк. В stdout — JSON-массив строк, в
  stderr — «строк: N из total».
- Без `--all` в stdout — `result`, а `total` и `next` — в stderr.
- `--raw` — ответ целиком (с `time`: `date_start`, `operating`).

Кавычки: в zsh и bash параметры со скобками `[]` брать в одинарные кавычки,
иначе оболочка примет их за шаблон файлов. В PowerShell кавычки не нужны, но
JSON в `--json` удобнее передать файлом `@params.json`.

```bash
b24 call profile
b24 call crm.deal.fields
b24 call crm.deal.list 'filter[CATEGORY_ID]=0' 'filter[STAGE_SEMANTIC_ID]=S' 'select[]=ID' 'select[]=OPPORTUNITY' --all
b24 call crm.item.list --json '{"entityTypeId":1036,"filter":{">=createdTime":"2026-01-01T00:00:00+03:00"},"select":["id","title","stageId"]}' --all --limit 2000
b24 call --key lab user.get 'filter[ACTIVE]=true' --all > users.json
```

### Пачка

```text
b24 batch [--key имя] [--halt] имя=метод?параметры ...   |   --json '{"имя":"метод?параметры"}'
```

```bash
b24 batch 'd=crm.deal.get?id=12' 'u=user.get?ID=$result[d][ASSIGNED_BY_ID]'
```

Больше 50 команд делятся на несколько запросов сами. `$result[имя]…` — ссылка
на ответ другой команды той же пачки. Ответ: `result`, `result_error`,
`result_total`, `result_next` по именам команд.

## Прочее

| Команда | Что делает |
|---|---|
| `b24 status` | версия, ключи, подключены ли MCP-серверы, установлен ли скилл |
| `b24 setup [--print]` | подключить `b24-dev-mcp` и `b24` к Claude Code |
| `b24 mcp` | MCP-сервер на stdin/stdout (запускает Claude, не человек) |
| `b24 version` | версия |

Переменные окружения для проверок: `B24_HOME` — другая папка списка ключей,
`B24_KEYCHAIN_SERVICE` — другое имя записей в хранилище. Вместе дают
отдельный набор, не задевающий настоящие ключи.

Код возврата: 0 — успех, 1 — ошибка (текст в stderr, без ссылки ключа),
2 — неверные аргументы.

## Инструменты MCP-сервера b24

| Инструмент | Параметры | Что делает |
|---|---|---|
| `bitrix_keys` | — | ключи: имя, портал, пользователь, права, основной |
| `bitrix_read` | `key?`, `method`, `params?` | один вызов метода чтения; запись отклоняет |
| `bitrix_list_all` | `key?`, `method`, `params?`, `limit?` (500, до 20000) | все страницы списка: `{total, returned, items}` |
| `bitrix_batch` | `key?`, `commands`, `halt?` | пачка методов чтения; с записью — отказ |
| `bitrix_write` | `key?`, `method`, `params?` | любой метод, в том числе меняющий данные |

`params` — объект как в документации: `{"filter":{"STAGE_ID":"WON"},"select":["ID","TITLE"]}`.
Ответ длиннее 60 000 символов обрезается с подсказкой сузить выборку — ставь
`select` и `filter` заранее.

Чтение или запись определяется по имени метода: последнее слово `get`,
`list`, `fields`, `search`, `count`, `current` (и начинающиеся с `get…`) —
чтение. Исключения, которые меняют портал, хотя звучат как чтение:
`im.dialog.read`, `im.recent.hide`, `disk.file.getExternalLink` и подобные.
Неизвестное — запись.
